# v1.1: F, better French dubbing text with free resources (2026-11-23)

Goal: kids dub English YouTube videos (MrBeast, NBA) into French. The French should be clean, easy to say aloud and fit the time slot. When YouTube has its own French dub, use that instead.

## Changes
| File | Change |
|---|---|
| `content/captions.ts` | **Speaker markers survive.** `mergeSentences` now copies `newSpeaker` onto `Line.newSpeaker`. This was S's open issue 1. A speaker change still always starts a new line. `[NAME]:` labels now count as a speaker change. `>>`, `- ` and `NAME:` were already handled. The marker text is stripped. Sung lyrics (`♪ … ♪`, or a cue that only opens or closes a song) are dropped and not spoken. |
| `content/text/cleanup.ts` (new) | `cleanSourceText(text, lang)` runs on cues **before** merging and translating. It removes leftover non-speech tags and lyrics. For English only, it also removes hesitations (um/uh/er/hmm), filler phrases (`, you know,` · `I mean,` · `Like,` · `, like,`) and normalises casual words (kinda→kind of, gonna→going to, etc.). For all languages it removes stutters (`I- I- I` · `w-what` · `the the`). It also de-shouts: a line that is ≥ 60 % capitals becomes sentence case, and in normal lines ALL-CAPS words of 4+ letters are lowered. Known acronyms are kept (NBA, MVP, LA…). Proper names are put back (MrBeast, LeBron, Chandler, Lakers…). Numbers, `$` and names are left alone for the translator. |
| `content/text/glossary.ts` (new) | `frenchForSpeech` runs on every French output line, whichever translator produced it: tlang, Translator, OpenAI, or a track already in French. Money: `$10,000` / `10,000 $` / `10 000 $` / `$10K` → `10 000 dollars` (with a no-break space); `$1.5 million` → `1,5 million de dollars`; `1 $` → `1 dollar`; also handles €. `50%` → `50 pour cent`. English sports words the translator left in → French (3-pointer → tir à trois points, buzzer beater → tir au buzzer, free throw → lancer franc, rebound, assist, …). Pronunciation: `MrBeast` → `Mister Beast`, `NBA` → `N B A`, `MVP` → `M V P`, WNBA/NFL/ESPN/UFC, GOAT, OMG, `#3` → `numéro 3`. Leftover `euh`/`hum` are removed. Line count, ids and flags are kept, and a line is never emptied. |
| `content/text/nano.ts` (new) | **Smart French (Gemini Nano, Prompt API).** `FrenchShortener` takes the lines where estimated French speech (14 chars/s, via `sync/fit.estimateMs`) is longer than 1.25 × the slot. The slot runs to the line end plus up to 0.6 s of gap, and lines under 25 characters are skipped. It asks Nano, one line at a time, for a shorter natural spoken French line for kids with the same meaning, nothing added, names and numbers kept. The prompt includes the English source for meaning. It works ahead of playback from `fromTime` and never blocks. Each line has a 6 s timeout; after 3 consecutive failures the pass turns itself off. Debounced updates go out through `onUpdate`, and the pass stops when the session stops (`isAlive`). Output is checked: first line only, no quotes or labels, ≤ 92 % of the original length and ≥ 35 %, and the numbers must be unchanged; otherwise the original line is kept. One base session with a French system prompt is created and `clone()`d per line, so the context never grows. It uses `LanguageModel` in the isolated world when present, otherwise the MAIN world (bridge op `nano`). `warmUpNano()` runs inside the Dub click, because the model download needs user activation. It runs `availability()` and calls `create()` only when the model is downloadable or downloading. |
| `content/pipeline.ts` | Source cues are cleaned (`cleanCues`) before merging. A dropped cue's speaker flag moves to the next cue. `polish()`/`speechFriendly` runs on all target-language output. `getLines` wraps the raw pipeline with the Nano shortener when `smartFrench && lang==='fr' && onUpdate`. The cache keeps the unshortened lines, and Nano runs again for each session. The cache key changed to `lines:<id>:<lang>:2`, so v1.0 entries (no cleanup, no flags) are ignored. New options: `smartFrench`, `isAlive`, `rewrite` (for tests). |
| `content/main-hook.ts` | **Official audio track.** `switchAudioTrack(videoId, lang)` and `restoreAudioTrack(videoId)` use `movie_player.getAvailableAudioTracks()`, `getAudioTrack()` and `setAudioTrack(track)`. Track objects are minified, so `audioTrackInfo` finds the nested `{id:'fr.3', name}` by looking through the object's keys. Display names from the player response (`adaptiveFormats.audioTrack`) are the fallback. After switching it reads `getAudioTrack` back to check. It refuses when the player is on another video. It saves the previous track per video. New bridge ops: `nano`, `nanoWarmup`, `translatorWarmup`, `audioTrackSwitch`, `audioTrackRestore`. |
| `content/yt.ts` | `switchToOfficialAudio(videoId, lang)` and `restoreOfficialAudio(videoId)` (both return immediately when there is no `#movie_player`). |
| `content/session.ts` (small hooks) | New deps: `warmUpNano`, `switchOfficialAudio`, `restoreOfficialAudio`. In `start()`, the warm-ups run before the first await. Then, if `preferOfficialAudio` is on and the switch succeeds, pitch stops and the status becomes `dubbing` with `usingOfficialAudio: true`, `officialTrackLang` and the message "Using YouTube's official French audio". No captions or TTS are loaded. Otherwise normal dubbing runs. `teardown()` restores the track, but only if we changed it. Changing `preferOfficialAudio` restarts the session. `getLines` receives `smartFrench` and `isAlive`. `warmUpTranslator` now falls back to the MAIN-world `translatorWarmup` when the isolated world has no `Translator` (A's open issue 2). |
| `shared/*` (additive) | `Settings.smartFrench` (default true) and `Settings.preferOfficialAudio` (default true), both normalised. `DubStatus.usingOfficialAudio?`. Extra `BridgeOp` values. |
| `index.ts`, `background/translate.ts` | No change needed. |

## Translator choice and evidence
- **Human captions: YouTube `tlang` first** (unchanged). It is Google Translate quality on proper sentences. It now also gets the FR polish.
- **ASR captions: Chrome Translator first, then tlang** (A's order kept). I did **not** run a live benchmark. The Translator API is not exposed in Playwright's bundled Chromium, and these tests mock it. Reasoning:
  1. For ASR, tlang translates each ~2-second caption fragment on its own, so French word order breaks across cue boundaries, and timings follow the English fragments.
  2. We translate **after** merging and cleanup. The Translator then sees whole clean sentences (no "um, like", no shouting, no `[Music]`), which is the biggest quality gain for a small on-device model.
  3. It works offline and has no 429 risk, which tlang has (one try per video).
  Worth a real-Chrome A/B on 2–3 MrBeast ASR videos. If Translator French reads clearly worse, swap the order in `pipeline.ts`; it is one `if (asr)` block.
- **Prompt API availability (docs):** the `LanguageModel` global works in extensions from Chrome 138. `expectedInputs`/`expectedOutputs` support en/ja/es/de/fr. `create()` for a download needs user activation. In extensions, pass both or neither of `topK`/`temperature`; we pass neither. The docs do **not** say clearly whether content scripts get the global. A Chromium doc says "extension window and worker scripts", and a 2024 forum post reports content-script failures. So the code tries the isolated world, then the MAIN world. If neither has it, the pass turns itself off after 3 failures and nothing breaks.
- **Audio-track API:** undocumented. The method names are confirmed from a maintained userscript (Greasy Fork "YouTube default audio track": `getAvailableAudioTracks`, `getAudioTrack`, `setAudioTrack(track)`, language/name in a nested minified object).

## Open issues
1. **Not checked in real Chrome:** whether `LanguageModel` exists in the isolated or MAIN world of a content script; Nano latency per line (the 6 s timeout is a guess); and whether `setAudioTrack` keeps playback position and plays immediately.
2. **The Nano pass waits on `create()`** while the model downloads (GBs) and stays idle until the download finishes. Lines played before then keep their long text, which is harmless.
3. `10 000` with a no-break space: Apple French voices read it as "dix mille". Piper/espeak should also, but this is unverified. If a voice says "dix, zéro zéro zéro", switch to digits with no separator (one line in `frenchNumber`).
4. Subtitles show the TTS form ("N B A", "Mister Beast"), because `Line.text` serves both. If that bothers kids, add a `Line.say?` field (B/P would read it).
5. De-shouting lowercases unknown 4+ letter acronyms in shouted lines, and names missing from `PROPER` come out lowercase in shouted lines (the translator usually copes). Extend the lists as videos show gaps.
6. An official track counts only when the player has ≥ 2 audio tracks. If YouTube already auto-selected French (FR browser locale), we report "official audio" and restore nothing, which is correct.
7. Nano rewrites are not cached; they are redone each session (free, on-device).
