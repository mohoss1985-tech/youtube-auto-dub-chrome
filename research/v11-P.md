## 2. New engine `'neural'` (Piper, fully in the browser)
**Library choice.** I wrote a small engine directly on **onnxruntime-web 1.31.1** (`onnxruntime-web/wasm`, MIT) plus **@diffusionstudio/piper-wasm 1.0.0** (the emscripten build of rhasspy piper-phonemize / espeak-ng, MIT). I did not use `@mintplex-labs/piper-tts-web 1.0.5` for these reasons:
- It is a hard-wired singleton.
- It loads WASM from jsdelivr/cdnjs by default.
- It downloads from a diffusionstudio mirror of the models.
- It always uses speaker 0, so multi-speaker models such as upmc and sharvard don't work.
- It re-fetches the 18 MB phonemizer data for every chunk.

My version compiles the phonemizer WASM once and hands over the `.data` buffer through `getPreloadedPackage`. Inference uses the model's own `speaker_id_map`. Output is peak-normalised and silence-trimmed, so `knownMs` is the real speech length.

**Architecture (MV3, no remote code)**
- Content script → `NEURAL_TTS` → service worker (`src/background/neural.ts`) → offscreen document (`offscreen.html`, reason `WORKERS`) → module Worker (`piper-worker.js`) → WAV/base64. The audio then plays through the existing `AudioEngine` `<audio>` path, with exact `knownMs`.
- All JS and `.wasm` files ship in the package:
  - `ort/ort-wasm-simd-threaded.wasm` (14.8 MB)
  - `piper/piper_phonemize.wasm` (0.6 MB)
  - `piper/piper_phonemize.data` (18 MB of espeak data)
- Only model **data** (`.onnx` and `.onnx.json`) comes from `huggingface.co/rhasspy/piper-voices/resolve/main`. CORS works, and I checked it with a real download. Models are cached with the Cache API (`autodub-piper-v1`) in the extension origin.
- Manifest changes:
  - `permissions` gains `offscreen` and `unlimitedStorage`.
  - `content_security_policy.extension_pages` = `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'`.
  - **COOP/COEP keys** (`cross_origin_opener_policy: same-origin` and `cross_origin_embedder_policy: require-corp`) make extension pages `crossOriginIsolated`, so ORT runs 4 WASM threads. That roughly halves the RTF compared with 1 thread. There is no effect on content scripts or YouTube.
- Messages are additive:
  - `NEURAL_TTS {text, lang, voice}` → `{audioB64, mime, ms, rtf, threads}`, or `{pending, progress}` while the model downloads.
  - `NEURAL_STATUS {models, download?, remove?}` → `{models: NeuralModelState[]}`.
  - The SW mirrors which models are ready into `chrome.storage.local.neuralReady`.
- Types and settings: `EngineId` gains `'neural'`, `ENGINES` includes it, and `Settings.preferNeural` defaults to true. I also added `NeuralTtsRequest`, `NeuralTtsResult` and `NeuralModelState`.
- `createEngine('neural')` returns a `NeuralEngine` (`src/content/voice/neural.ts`):
  - **Model not downloaded yet:** the line plays through Web Speech with a voice of the same gender, so there is no silence. The download starts automatically, and the engine backs off for 3 s between checks.
  - **When the model is ready:** later lines use neural audio.
  - **After 3 errors in a row:** it calls `onFallback` once, and the session switches to Web Speech with a toast.
- Popup:
  - The Engine section lists "Neural voices — Free, on this computer · ~60 MB per voice" first, with a "Recommended for French" pill and a "Best free" tag.
  - A panel lists the voices labelled Male/Female, with Ready / % / Not downloaded states. It has a **Download French voices (127 MB)** button and a progress bar (polls every 0.7 s).
  - When the French models are ready, `preferNeural` switches the engine to `neural`. Choosing Browser voices yourself sets `preferNeural:false`.
  - The voice list marks voices that are "not downloaded".
  - The popup's design tokens are kept.

The AGPL licence on Tom and the NC licences only matter for a commercial or Store release. Piper has no female ar or tr voice, so for those languages the female lines use Web Speech.

| Voice | 1 thread (tab probe) | 4 threads, isolated (offscreen, full SW path) |

| Siwis | RTF 0.167 | **RTF 0.06–0.12** (0.25–0.5 s) |

| Pierre / Jessica | RTF 0.16 | RTF 0.05 |

Cold start (first line, model load): about 2 s. The target RTF < 0.3 is met with a wide margin, so prefetch keeps up easily.

Samples to listen to are in `research/samples/`:
- `fr-female-siwis.wav`
- `fr-male-tom.wav`
- alternates `fr-male-pierre-alt.wav` and `fr-female-jessica-alt.wav`

Sizes: the package grows by ~33 MB (ORT wasm plus espeak data). Each voice is 63–77 MB once, cached. Each WAV line is ~45 KB/s (Tom ~90 KB/s) and travels as base64 over messaging.

## Open issues
- **Cast to TV:** the neural audio plays from the content script's `<audio>`, so it is part of the tab. I expect it to cast like the API engines, but I have not tested it.
- The ORT threads need COOP/COEP on extension pages. If a later feature embeds cross-origin resources in the popup, they would need CORP. Without isolation, the code falls back to 1 thread (RTF Tom ≈ 0.3).
- Downloads start automatically when engine = `neural` and the target-language model is missing. The popup states the size, but there is no confirmation step.
- Tom vs Pierre quality was chosen from community feedback plus the sample rate. The owner should listen to the samples and swap `recommended` in `neural-catalog.ts` if needed.
- espeak French reads numbers and "$" itself (e.g. "100 000 $"). Text normalisation is minimal: caption noise like [Musique] is stripped.
- The macOS voice names for ar/tr in `MAC_HQ_VOICES` have not been verified.
